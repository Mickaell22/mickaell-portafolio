## Context

A real client — a special therapy and education center that managed everything on paper and spreadsheets. The project came in two phases: first a basic system, then a full expansion of it.

## Scope

The system covers the center's complete operation:

- **Patients:** registration, history, documents, guardians, treatment pauses
- **Therapeutic module:** sessions, schedules, attendance, statistics per therapist
- **Pedagogical module:** pedagogical sessions, evaluations, schedules, attendance
- **Staff:** therapists, educators, specialties, documents
- **Users and roles:** administrator, therapist, educator — each sees only their own
- **Reports:** PDF generation with history and statistics
- **Internal chat:** messaging between the center's staff
- **Notifications:** real-time notification system

## Project size

190+ components in the frontend. The largest project by lines of code I've delivered.

## Tech stack

**Frontend:** React with Material UI, Vite, Redux Toolkit, custom hooks per entity. Role-protected routes. Theme customizable from the backend (center name, colors, general settings).

**Backend:** Python with a REST API. PostgreSQL. Deployed on Railway.

## What I learned

Managing a project of this scale with a non-technical client requires constantly documenting decisions. I also learned that healthcare systems have privacy requirements that change the whole design from the start.

## Status

Delivered. In active use by the center.
