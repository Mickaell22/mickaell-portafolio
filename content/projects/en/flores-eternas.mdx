## Context

A real client — a handmade fabric flower shop that needed a full e-commerce platform with valid electronic invoicing for Ecuador. The SRI integration was the technical core of the project.

## Electronic invoicing — SRI

The system builds the electronic receipt for Ecuador's Servicio de Rentas Internas (tax authority). What is implemented:

1. XML generation with the structure the SRI requires
2. Computation of the **49-digit access key**, with its mod-11 check digit
3. Building the **SOAP envelope** and submitting it to the reception and authorization webservices
4. Reading and storing the response

This is not a modern REST API integration — the SRI uses SOAP and XML with a specific schema that very few developers have worked with.

**Honest status:** it runs against the SRI's **test environment** (`SRI_AMBIENTE=1`) and the **XAdES-BES signature is still pending**, marked as a TODO in the service. Without that signature there is no authorized receipt in production, so I describe it for what it is: XML, access key and SOAP transport solved; digital signature, not yet.

## E-commerce features

- Product catalog with images and categories
- Cart and checkout flow
- Roles: ADMIN / SELLER / CLIENT
- Admin panel with inventory management
- Order and invoice history per customer

## Security and validation

Rate limiting, Helmet for HTTP headers and input sanitization. Every input goes through **Zod schemas** (auth, products, orders, users, customers and SRI) applied from a single middleware, so no controller ever receives unvalidated data. This was not an academic project — it handled real customer data.

## Tech stack

**Backend:** Node.js + Express 5 + Prisma ORM + PostgreSQL. JWT for authentication, Zod for validation, Jest + Supertest for the test suite.

**Frontend:** React with Tailwind CSS and Zustand for global state.

## Why it stands out

Ecuador's SRI integration is a very specific technical niche. Most experienced developers in Ecuador have never touched it. In an interview with an Ecuadorian company it opens very different conversations — especially if you know exactly which part is solved and which isn't.
