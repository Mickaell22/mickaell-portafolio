## Context

Working with several repositories at once, the models' context filled up fast: to understand part of a project, Claude Code read whole files. I built my own MCP server that indexes the code once and returns only what is relevant to each question.

## How it works

1. It indexes a local repo or clones it from GitHub. Indexing is read-only: it never modifies the project's files
2. Each file is split by functions, classes or components; embeddings are computed on CPU and stored in ChromaDB
3. For each question it combines semantic and lexical search to pick the chunks
4. DeepSeek Flash summarizes them and Claude Code receives the summary with `file:line` citations
5. On a real query over its own repo: ~770 tokens instead of ~12,100 reading the 4 files in full

Beyond queries it has 13 tools: code audit with a false-positive verification pass, import graph, project profile and detection of stale repos or indexes.

## One machine or several

It runs on a single machine with a local PostgreSQL, or on several pointing to the same database: each machine keeps its own path to each project and its own index, and they share the registry, metrics and import graph.

## Security

It only indexes whitelisted paths, blocks `.env`, keys and certificates, and respects each repo's `.gitignore`. The GitHub token lives only in memory and is never written to `.git/config`.

## Real use

I use it daily with Claude Code across all my projects, and it was used while building this portfolio to analyze the 58 GitHub repositories and classify them.

## Tech stack

Python with the MCP SDK. ChromaDB for vectors, PostgreSQL for the registry and metrics. `all-MiniLM-L6-v2` embeddings on CPU. DeepSeek Flash to summarize and audit. GitPython to clone and detect changes.

## Status

Active. In daily use and published on GitHub, with an install guide for one or several machines.
