## Contexto

Trabajando con varios repositorios a la vez, el contexto de los modelos se llenaba rápido: para entender una parte del proyecto, Claude Code leía archivos completos. Construí mi propio servidor MCP que indexa el código una vez y devuelve solo lo relevante a cada pregunta.

## Cómo funciona

1. Indexa un repo local o lo clona de GitHub. Indexar es de solo lectura: nunca modifica los archivos del proyecto
2. Cada archivo se parte por funciones, clases o componentes, y los embeddings se calculan en CPU y se guardan en ChromaDB
3. Ante una pregunta, combina búsqueda semántica y léxica para elegir los fragmentos
4. DeepSeek Flash los resume y Claude Code recibe el resumen con citas `archivo:linea`
5. En una consulta real sobre el propio repo: ~770 tokens en vez de ~12.100 leyendo los 4 archivos enteros

Además de consultar, tiene 13 tools: auditoría de código con verificación de falsos positivos, grafo de imports, perfil del proyecto y detección de repos o indices desactualizados.

## Uno o varios equipos

Funciona en un solo equipo con una PostgreSQL local, o en varios apuntando a la misma base: cada equipo guarda su propia ruta de cada proyecto y su propio indice, y comparten el registro, las métricas y el grafo de imports.

## Seguridad

Solo indexa rutas de una whitelist, bloquea `.env`, llaves y certificados, y respeta el `.gitignore` de cada repo. El token de GitHub viaja solo en memoria y nunca se escribe en `.git/config`.

## Uso real

Lo uso a diario con Claude Code en todos mis proyectos, y se uso durante la construcción de este portafolio para analizar los 58 repositorios de GitHub y clasificarlos.

## Stack técnico

Python con el SDK de MCP. ChromaDB para los vectores, PostgreSQL para el registro y las métricas. Embeddings `all-MiniLM-L6-v2` en CPU. DeepSeek Flash para resumir y auditar. GitPython para clonar y detectar cambios.
